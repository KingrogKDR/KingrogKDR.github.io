The Need for a Custom Kubernetes Scheduler

March 31, 2026

What a Kubernetes Scheduler does

A Kubernetes Scheduler is a component that decides which machine (node) should run a new Pod.

When a Pod is created, it starts in a waiting state. The scheduler looks at all available nodes and picks the best one where the Pod can run properly.

How the scheduler makes decisions

To decide where a Pod should run, the scheduler uses two types of rules.

Hard rules called Predicates (must follow): these cannot be broken. For example, the node must have enough CPU and memory.

Soft rules called Priorities (good to have): these are preferences. For example, prefer nodes with GPUs or nodes that are less busy.

The scheduling process

The scheduler works in two simple steps.

Filter: remove nodes that do not satisfy the hard rules.

Sort: from the filtered nodes, pick the best one based on preferences or the soft rules.

Simple mental model

All nodes

↓ remove bad options

Valid nodes

↓ pick the best one

Final node

Why we might need a custom scheduler

The default scheduler in Kubernetes works well for most cases.

But sometimes we need more control over how Pods are placed.

For example, we may want machine learning jobs to run on GPU machines first.

Or we may want our applications to run in specific regions.

Or we may have special rules that are not supported by the default scheduler.

In these cases, we can build our own scheduler.

How a custom scheduler fits into Kubernetes

A custom scheduler can run alongside the default scheduler.

We can have multiple schedulers running at the same time.

When creating a Pod, we can choose which scheduler to use by setting schedulerName.

The scheduler itself runs like a normal Pod inside the cluster.
