## Creating a New Post

### Step 1 — Write the post Markdown file

Create a new file in `blogs/` named `{slug}.md`. The file has two parts, separated
by a line containing only `---`:

1. A **frontmatter block** — a JSON object (no trailing commas!) with the post's metadata.
2. The **post body** — plain Markdown.

```md
{
"title": "Your Post Title",
"slug": "your-post-title",
"date": "2026-08-09",
"tag": ["Tag One", "Tag Two"],
"excerpt": "A one or two sentence summary shown in listings and share cards.",
"pinned": false
}

---

Your post starts here. Regular **Markdown** works — headings, bold, links,
blockquotes, images, code fences, etc.
```

> Set `"pinned": true` to feature it on the homepage.

> ⚠️ **Watch for trailing commas.** The frontmatter block is parsed with
> `JSON.parse()`, so a trailing comma after the last field (e.g. `"pinned": true,`)
> will silently break the parser for that post. If a post fails to load on
> `writing.html` (dropped quietly) or breaks the whole pinned section on
> `index.html` (hard failure), check the frontmatter JSON first.

### Step 2 — Add the OG image (optional)

Place a `1200×630px` image somewhere under `images/`, e.g. `images/og/your-post-title.jpg`,
and reference it from the frontmatter as `"og-image": "images/og/your-post-title.jpg"`.
If you skip this, it falls back to the series image (if any), then `images/og-default.png`.

### Step 3 — Add the slug to `BLOGS`

Both `index.html` and `writing.html` keep their own `BLOGS` array. Add your slug to **both**:

```js
const BLOGS = [
  "designing-metrics-for-athens-go-module-proxy",
  "flavors-of-io",
  "your-post-title", // ← add here
];
```

### Step 4 — Build the static share pages

```bash
npm install marked   # first time only
node build-og.js
```

This reads every `blogs/*.md` file directly (it doesn't use the `BLOGS` array) and
generates `post/your-post-title.html` — the URL you share on social media — with
real, crawler-readable OG tags baked in.

### Step 5 — Commit and push

```bash
git add blogs/your-post-title.md post/your-post-title.html images/og/your-post-title.jpg
git commit -m "post: add your-post-title"
git push
```

### Step 6 — Share the correct URL

```
https://kingrogkdr.github.io/post/your-post-title.html
```

> ⚠️ Do **not** share `post.html?slug=...` — that URL has no baked-in OG tags and will show a blank card on Twitter/WhatsApp. Always share the `post/{slug}.html` file generated by `build-og.js`.

## Creating a Series Post

### Step 1 — Add or update the series in `blogs/series.json`

```json
[
  {
    "id": "your-series-id",
    "title": "Your Series Title",
    "description": "What this series is about.",
    "og-image": "images/og/your-series.jpg",
    "posts": ["first-post-slug", "second-post-slug"]
  }
]
```

Posts are listed in order. If a slug's `.md` file doesn't exist yet, it shows as
**Coming soon** automatically on `writing.html`, `post.html`, and `series.html`.

### Step 2 — Write the post Markdown file

Same as a standalone post, but add a `"series"` field to the frontmatter matching the series `id`:

```md
{
"title": "Your Series Post Title",
"slug": "first-post-slug",
"date": "2026-04-01",
"tag": ["Kubernetes", "Systems"],
"excerpt": "What this part covers.",
"series": "your-series-id",
"og-image": "images/og/first-post.jpg",
"pinned": false
}

---

Your post body in Markdown...
```

> If a post has no `"og-image"`, it falls back to the series `"og-image"`, then to `images/og-default.png`.

### Step 3 — Add the slug to `BLOGS` in both `index.html` and `writing.html`

### Step 4 — Build static pages

```bash
node build-og.js
```

Generates both:

- `post/first-post-slug.html` — the post page (with series banner + prev/next)
- `series/your-series-id.html` — the series index page

### Step 5 — Commit and push

```bash
git add blogs/ post/ series/ images/
git commit -m "post: add first-post-slug (series: your-series-id)"
git push
```

### Step 6 — Share URLs

```
Post:   https://kingrogkdr.github.io/post/first-post-slug.html
Series: https://kingrogkdr.github.io/series/your-series-id.html
```

## Post Frontmatter Structure

| Field         | Type            | Required | Description                                     |
| ------------- | --------------- | -------- | ----------------------------------------------- |
| `title`       | string          | ✅       | Post title                                      |
| `slug`        | string          | ✅       | URL-safe identifier, must match filename        |
| `date`        | string          | ✅       | ISO date: `"2026-04-01"`                        |
| `tag`         | string or array | ✅       | One tag or array of tags                        |
| `excerpt`     | string          | ✅       | Short summary (used in listings + share cards)  |
| `series`      | string          | —        | Series `id` if this post belongs to one         |
| `og-image`    | string          | —        | Path to share card image (1200×630px)           |
| `pinned`      | boolean         | —        | `true` to show on homepage                      |
| `updated`     | string          | —        | ISO date of last edit (used in OG meta)         |
| `description` | string          | —        | Overrides `excerpt` for meta description if set |

The frontmatter block **must be valid JSON** — no trailing commas, keys quoted, etc.
Everything after the `---` line is the post body and is plain Markdown.

## Post Content Formatting

Post bodies are rendered with [`marked`](https://github.com/markedjs/marked) —
standard Markdown — plus a few conventions the site's post-processing (in
`post.html` client-side, and mirrored in `build-og.js` for the static export)
looks for:

### Headings

`#`, `##`, `###` (h1–h3) get an id generated from their text and are picked up
by the table-of-contents sidebar. Fewer than 2 headings in a post → no TOC is shown.

### Highlight

Obsidian-style `==highlighted text==` renders as `<mark>`:

```md
==this gets highlighted==
```

### Images with captions

A standard Markdown image on its own line, immediately followed by an _italicised_
paragraph, becomes a captioned figure — the italic paragraph is consumed as the caption:

```md
![Alt text](images/folder/photo.png)

_Optional caption shown below the image._
```

### Code blocks with captions

A fenced code block, immediately followed by an _italicised_ paragraph, gets the
site's code-block chrome (language label + copy button) and the italic paragraph
becomes a caption below it:

````md
```go
func main() {
    fmt.Println("hello")
}
```

_Optional caption below the block._
````

### Callouts (Obsidian-style)

A blockquote whose first line is `[!type]` becomes a styled note/tip/warning box:

```md
> [!note]
> Your note text here.

> [!warning]
> Be careful with this.

> [!tip]
> Pro tip: use labels for better filtering.
```

Recognized types map down to three visual styles:

| Type(s)                                     | Rendered as |
| ------------------------------------------- | ----------- |
| `note`, `info`                              | info        |
| `tip`, `success`                            | tip         |
| `warning`, `caution`, `important`, `danger` | warning     |

If you just want a plain blockquote (no callout box), don't start it with `[!type]` —
e.g. `> ==highlighted quote text==` renders as a normal blockquote with highlighted
text inside it, not a callout.

### Everything else

Standard Markdown: `**bold**`, `*italic*`, `` `inline code` ``, `[links](url)`,
`- bullet lists`, `1. numbered lists`, fenced code blocks with a language tag for
syntax highlighting, etc.

## Bio Formatting (cv.json)

`bio_long` strings support **raw HTML** — write tags directly:

```json
"bio_long": [
  "I'm <strong>Abhishek Saikia</strong>, a programmer and thinker based in <mark>India</mark>.",
  "I work in <strong>backend and systems engineering</strong> — distributed systems, cloud, and computer internals. Comfortable in <strong>Go</strong>, <strong>TypeScript</strong>, <strong>Python</strong>, and a bit of <u>Rust</u> and <u>C</u>.",
  "I write here irregularly but with intention.",
  "If something I've written resonated with you, <a href='contact.html'>I'd genuinely love to hear about it</a>."
]
```

Supported HTML you can use freely:

| Tag                                   | Effect       |
| ------------------------------------- | ------------ |
| `<strong>text</strong>`               | Bold         |
| `<em>text</em>`                       | Italic       |
| `<u>text</u>`                         | Underline    |
| `<mark>text</mark>`                   | Highlight    |
| `<code>text</code>`                   | Inline code  |
| `<a href="...">text</a>`              | Link         |
| `<span style="color:red">text</span>` | Colored text |
| `<br>`                                | Line break   |

## OG Images (Share Cards)

| Situation                                        | Image used              |
| ------------------------------------------------ | ----------------------- |
| Post has `"og-image"`                            | Post's own image        |
| Post has no `"og-image"` but belongs to a series | Series `"og-image"`     |
| Neither post nor series has `"og-image"`         | `images/og-default.png` |

**Specs:** `1200 × 630px`, JPG or PNG.
**Location:** Anywhere under `images/` — recommended paths:

- Standalone posts → `images/og/post-slug.jpg`
- Series → `images/og/series-id.jpg`
- Post inline images → `images/series-id/image-name.jpg`

## After Publishing

### Bust social media caches

After pushing, if you shared a URL before and the card looks stale:

| Platform    | Tool                                                                                |
| ----------- | ----------------------------------------------------------------------------------- |
| Twitter / X | [cards-dev.twitter.com/validator](https://cards-dev.twitter.com/validator)          |
| Facebook    | [developers.facebook.com/tools/debug](https://developers.facebook.com/tools/debug/) |
| LinkedIn    | [linkedin.com/post-inspector](https://www.linkedin.com/post-inspector/)             |
| WhatsApp    | Append `?v=2` to the URL — WhatsApp treats it as a new link                         |

### Re-run build after edits

Any time you add or edit a post `.md` file or `series.json`, re-run the build and push:

```bash
node build-og.js
git add post/ series/
git commit -m "rebuild: update static pages"
git push
```
